# A CISO lane: governance is a different question from exploitation

**Date:** 2026-08-28 · **Status:** accepted · **Scope:** `src/roster.ts`, `src/crew-org.ts`,
`agent/council-ciso.md`, `README.md`

## Context

From the repo's owner:

> *"Can we recruit a CISO that understands the standard GRC, compliance, validates the
> output from a security perspective and reverts back to the workflow with the security
> concern."*

Three requirements: GRC and compliance judgement, validation of the output, and findings
that **feed back into the work** rather than landing in a report nobody actions.

The council already has a `security` lane, and it is a good one. `agent/council-security.md`
casts it as *"the adversary, the auditor, and the security conscience"*, working the OWASP
Top 10 and CWE, and it will not accept a finding without a step-by-step attack: *"If you
cannot write the steps, you do not have a finding."*

So the question this ADR answers is not "should the council care about security" — it
already does. It is **whether compliance is a separate question, or the same question in
different clothes.** If it is the same, this change buys a second model to write the first
model's sentence, which is exactly the trap that kept `techwriter` out of `ROUTES` one ADR
ago and is documented in the comment on `ROUTES` itself.

## Decision

1. **A `ciso` role joined `Role`, `ALL_ROLES` and the roster**, carried by `mimo` and
   `minimax`, with `agent/council-ciso.md`.
2. **Its prompt is written against `security`'s, not beside it.** The finding test is
   explicit: *"would Security have raised this? If yes, drop it."*
3. **It is grounded in the repo's own controls**, not framework boilerplate — it reads
   `docs/compliance*`, `SECURITY.md`, policy directories and `AGENTS.md` first and cites
   those. Frameworks are vocabulary only.
4. **Its `ROUTES` entries are not a copy of `security`'s.** `ciso` is absent from every
   source-code glob and wakes on governance surfaces instead.
5. **`recruitFloor` recruits it on regulated ground**, by extending the existing `AS_PATH`
   word→path table rather than adding a second keyword table.

## The line, stated concretely

The two lanes ask different questions of the same file:

| | `security` | `ciso` |
|---|---|---|
| the question | how do I break this? | does this put us out of compliance, and could we prove it? |
| the artefact | an attack scenario, step by step | a control, the gap, and what closes it |
| the citation | OWASP ASVS, CWE | the repo's own controls; frameworks only as vocabulary |
| owns | injection, forgery, escalation, bypass, crypto misuse | classification, least privilege *as governance*, evidence, retention, vendors, segregation of duties |

**The sharpest example, and the one the design was tested against.** A change adds a support
tool letting staff read a customer's records. The authentication is correct, the
authorisation check is correct, and there is no bypass — `security` reads it and has
**nothing to say, correctly**. The CISO's finding is that the action writes no audit record:
access is enforced but not *provable*. Six months later nobody can answer who read which
customer's data, and if a data subject asks, there is no answer to give.

Note which repo that example is *not* about. This one has no `SECURITY.md` and no
`docs/compliance/`, so a CISO reviewing a diff here is required by its own prompt to say
that no controls are stated and reason from the change's actual exposure instead — not to
cite SOC 2 CC7.2 at a repo that has never claimed SOC 2. The grounding rule is not
decoration; it is the difference between this lane and a boilerplate generator.

That finding is not weaker than a security finding. It is invisible to one, because *nothing
is exploitable* — and "correct" and "provable" are different states, only one of which
survives an audit. Two more of the same shape: PII in a debug log is not a vulnerability
(it is our own log) but it is a classification and retention problem the deletion path never
reaches; a new SDK that is not vulnerable is still an undisclosed subprocessor.

If findings of this shape cannot be produced, the roles are not distinct and this lane
should be deleted. They can, so it stays.

## The feedback loop is what makes tier discipline load-bearing

`reviewBranch` (`src/lets.ts`) maps **BLOCKER** findings to `WorkItem`s, and `queue =
review.items` feeds them straight back into execution, bounded by `MAX_REVIEW_CYCLES` = 3.
A CISO blocker therefore **becomes work that gets fixed** — which is precisely the "reverts
back to the workflow" the owner asked for, and it is not a report-only role.

That converts a prompt-quality problem into a budget problem, so the prompt says so
outright: a BLOCKER must name **the control, the gap, and what specifically closes it**,
because *"consider the compliance implications"* is unactionable and will consume one of
three cycles producing nothing. The prompt also records that a NIT receives **zero** skeptic
verification under `SKEPTICS_PER_TIER`, so a NIT is unverified by construction and must not
carry anything load-bearing.

## The carrier constraint, and a wrong reason corrected

`ciso` is carried by `mimo` and `minimax`. The binding constraint is that **neither carries
`security`**, and the mechanism is not the obvious one.

`selectNodes` deprioritises a model already used this round, which normally keeps two lanes
on two voices. But that only helps while unused carriers remain. `ciso` has **exactly two
carriers and `DEFAULT_MODELS_PER_ROLE` is two**, so the cap truncates nothing and *both
carriers always run*. A carrier that also held `security` would be handed both lanes on
every diff waking both — the governance finding written in the voice that just wrote the
attack, destroying the independence the second lane was bought for.

This was **measured, not reasoned**: putting `ciso` on `opus5` produces `security:opus5` and
`ciso:opus5` in the same round on `src/auth/session.ts`. That excludes `opus5`, `gpt56sol`
and `fable` — the obvious strong-reasoning picks.

**A first draft of this rationale was wrong and is recorded because the correction is the
useful part.** It claimed `glm53` was excluded because it carries `infrastructure`, which
co-fires with `ciso` on the IAM routes. A mutation test refuted it: with `ciso` on `glm53`
the panel is still all-distinct, because as a *third* carrier the used-count sort reaches
past it. The correlation risk is not "shares a co-firing lane"; it is "carrier count equals
the cap", which is a property of the arithmetic rather than of the role list. `glm53` was
passed over on load (three lanes already). The test that guards this asserts the
*behaviour* — no model answers two lanes on an IAM diff — rather than the proxy, and its
comment records the mutation that proves it is not vacuous.

## Routing: conservative, and deliberately not a mirror

`ciso` appears in **no source-code glob at all**. "Is this exploitable" is the question its
prompt forbids it to ask, so an ordinary `.ts` or `.go` diff must not pay for the lane.

| route | why |
|---|---|
| the `auth`/`session`/`token`/`crypto`/`secret` glob — **shared with `security`** | the one deliberate overlap: same file, two questions. Security asks whether the token can be forged; the CISO asks whether the access is least privilege and whether its use is provable |
| `**/*{iam,rbac,policy,policies,permission,permissions,authz}*` | access control as a governed artefact, in any language. **Narrower than `*.tf` on purpose** — routing every terraform diff here would put the CISO on tag renames. `role`/`roles` excluded despite fitting: too common in ordinary source to carry signal |
| `**/.env*` | secrets and third-party endpoints |
| dependency **manifests** | a declared dependency is a new subprocessor. **Never lockfiles** — `package-lock.json` and `go.sum` churn on transitive bumps nobody decided; a manifest edit is someone *choosing* a vendor |
| `SECURITY.md`, `COMPLIANCE.md`, `PRIVACY.md`, `compliance/`, `policies/`, `governance/` | the repo's own control surface: the commitments every other finding is measured against |

Deliberately **not** routed: all of `*.tf` (the infrastructure lane already reads IAM
wildcards and blast radius), and migrations. Migrations are the strongest omission — schema
is where retention and classification actually live — and are left out to keep the lane
conservative on first introduction. They are the first thing to add on evidence.

`recruitFloor` reaches the lane through `AS_PATH`, which maps a prose word to a **path,
never to a role**, so which lanes a signal wakes stays in `ROUTES` — one routing table, not
two. Only vocabulary that does not already route was added (`gdpr`, `pci`, `sox`, `audit`,
`retention`, `pii` and similar); `compliance`, `policy`, `iam`, `rbac` and `authz` reach the
lane unaided and restating them would be a second place to keep in sync.

## Alternatives rejected

**Extend `agent/council-security.md` to cover compliance.** The smallest diff, and it
destroys the lane that works. That prompt's discipline is *"if you cannot write the attack
steps, you do not have a finding"* — the exact rule that makes it trustworthy, and the exact
rule a compliance finding must break, because the audit-record gap has no attack steps.
Adding governance to it either loosens the attack requirement for everything, or gets
compliance findings suppressed by a rule written to suppress speculation. One prompt cannot
hold two contradictory evidence standards.

**A compliance checklist in `decide.ts` instead of a model.** Deterministic and cheap, and
it answers the wrong question. A checklist can assert "an audit-log call exists"; it cannot
judge whether *this* action needed one. The owner asked for judgement, and control
applicability is exactly the judgement part.

**Mirror `security`'s routes.** The obvious implementation and the one that would have made
this change indefensible: two models on every source diff, the second told not to say what
the first says. Cost with no added question.

**Route on all of `*.tf`.** Rejected as too wide. IAM-shaped paths carry the governance
signal; a tag rename does not.

**Route on lockfiles as well as manifests.** Would wake the lane on every `npm install` for
a vendor decision nobody took.

**Carry `ciso` on `opus5` and `gpt56sol`.** The strongest reasoners in the roster, and both
carry `security` — which, with two carriers and a cap of two, guarantees the collapse this
design exists to prevent. Measured, not assumed.

**A report-only role, with no path back into execution.** This is what the owner explicitly
ruled out, and `reviewBranch` already had the machinery to avoid it. The cost of using it is
that a sloppy blocker now consumes an execution cycle, which is why the prompt carries the
tier discipline it does.

## Consequences

- **Every full `/council:review` is 2 nodes more expensive: 25 → 27, measured.** That is
  ~8% on the most expensive path in the system, paid on every full review whether or not
  the change has a compliance surface. The figure is pinned in `src/roster.test.ts` rather
  than described, because "it only adds a couple of nodes" is how a cost stops being
  noticed. A future reader arguing to remove this lane should argue from what it *said*,
  not from this number alone.
- **Routed reviews are cheaper than that, and usually pay nothing.** `ciso` is absent from
  every source-code glob, so a normal diff does not wake it at all.
- **A CISO BLOCKER now consumes an execution cycle.** Three exist. A vague blocker is not a
  nuisance, it is a third of the budget, and the only thing preventing that is prompt
  discipline — there is no code-level check that a blocker is actionable.
- **The lane's independence rests on a roster invariant that is easy to break silently.**
  Adding `ciso` to a `security` carrier would collapse both lanes onto one model with no
  visible symptom. Two tests guard it: one on the role lists, one on the resulting panel.
- **`mimo` and `minimax` go from two lanes to three.** Neither was near the top of the load
  table; `gpt56terra` still carries four.
- **The framework vocabulary is a standing risk.** A model given the words "SOC 2" and
  "GDPR" will reach for them. The prompt's instruction to read the repo's controls first
  and to say when none exist is the entire mitigation, and it is a prompt-level one — if
  this lane starts producing boilerplate clause-citations at repos that never claimed the
  framework, that is the failure to watch for, and it is the signal to remove the lane.
- **Migrations are unrouted**, so retention and classification changes that arrive as schema
  will be missed unless another route catches the diff.
